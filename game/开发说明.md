# 《夏日幻想》开发说明

## 一、完成概览

- 引擎：WebGAL 4.6.6
- 入口：`game/scene/start.txt`
- 场景：序章 + 第一至第七章 + 两个结局，共 11 个 `.txt` 文件

- 选择点：10 处；结局：GOOD / BAD 双结局

- 背景：22 张 1920×1080 WebP，21 张已按章节接入；`title_bg.webp` 作为标题图备用
- 已验证：完整好线、送伞分支、学业不足、好感不足、开黑、退出、无礼物、支线覆盖八条路线均能正确到达对应结局

### 升学冲刺与判定

`ch07_final.txt` 先自动执行 `study = study + 20`，然后按顺序检查：

1. `key1 == "game"` → 提前坏线；
2. `key2 == "nogift"` → 提前坏线；
3. `gave_up == true` → 提前坏线；
4. 否则进入复习选择：
   - 每周和乐茹去图书馆自习：`study +10`，好感 +5；
   - 偶尔复习一下：`study +3`；
   - 实在顾不上，经常缺席：`study −5`，好感 −5；
5. 最终判定：`leru_fav >= 55` 且 `study >= 50` → GOOD END，否则 BAD END。

好线学业值：初始 20 + 第七章自动 20 + 每周图书馆 10 = **50**。选“偶尔复习”为 43，必定坏结局。

## 七、立绘与舞台

| 角色 | 模型 | 常用位置 |
| --- | --- | --- |
| 阮乐茹 | `figure/阮乐茹/leru.model3.json` | 居中 |
| 刘熙朗 | `figure/刘熙朗/liu.model3.json` | 左 / 右 / 居中 |
| 兰屿 | `figure/兰屿/lanyu.model3.json` | 左 / 右 |

三套模型统一以“上半身 + 脸部”为取景基准。乐茹、兰屿使用：

```text
-transform={"scale":{"x":2,"y":2},"position":{"y":760}}
```

刘熙朗的原始画布上下留白更大、人物在画布中位置偏低，同样参数下只能看到下半身。因此刘熙朗改用更大的缩放并整体上移：

```text
-transform={"scale":{"x":2.4,"y":2.4},"position":{"y":80}}
```

位于左侧时额外加 `"position":{"x":-120,"y":80}`，避免放大后过于靠边。该参数下刘熙朗的头部和上半身进入画面，取景与乐茹、兰屿一致；左右双人场景不重叠。全部 10 处刘熙朗出场语句已统一，`validate_scene.js` 检查为 0 错误、0 警告。

### 待机动作

所有真实立绘的 `changeFigure` 都带 `-motion=idle_lively`，进入场景时先播放一次 12 秒的待机动作。为保证动作结束后继续循环，三套 `*.model3.json` 的 `FileReferences.Motions` 中增加了首字母大写的 `Idle` 组，指向同一个 `Animation/idle_lively_v4.motion3.json`；WebGAL 只会自动预加载并循环 `Idle` 组，小写 `idle` 组不会被自动播放。另保留：

- `idle_lively`：12 秒完整待机，供 `-motion=` 单次调用；
- `idle`：约 6 秒的轻量待机，备用。

动作文件为 Cubism motion3 格式，`Segments` 采用 `[t0,v0, 0,t1,v1, ...]` 结构，`Meta.TotalSegmentCount` 与实际段数一致。`Groups.LipSync.Ids` 统一为 `["ParamMouthOpenY"]`。

### 模型文字清理

刘熙朗胸牌上的“X年一班”和兰屿 `水印.png` 部件上的防盗文字，均已直接从 `texture_00.png` 中清除：
- 兰屿：按 `Part148` 的 UV 范围把水印像素设为透明；
- 刘熙朗：按 `Part91` 胸牌的 UV 范围把文字区域填成胸牌底色。

没有修改 `.moc3` / `.model3.json`，模型动作、物理和参数不受影响。原始贴图备份在 `_test/model_backup/`；重新打开浏览器后截图检查，模型上半屏已无文字。

雨景使用：

```text
pixiInit;
pixiPerform:rain;
```

雨停使用 `pixiInit;` 重新初始化 Pixi，引擎会卸载所有 `PixiPerform` 演出。注意：`pixiPerform:none;` 只会注册一个名为 `PixiPerformnone` 的新演出，并不会停止正在下的雨。
